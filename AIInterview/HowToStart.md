
# To understand the code quickly as possible
- ask the `AI` to write comments on key classes so you don't have to read all the code.
- ask the `AI`, for a concise bulleted list of key functions per class and what they do.

# Work backwards from the testcases.
- You can also `add/update a test case to validate` your understanding.
- There can be commented unfinished testcases for you, to test your undersstanding. Fill them.

# Code generation
- write `comments for your approach` in the function that needs to be finished. Explaining your thought process to interviewer. `Brute force` is a good start.
- Ask `AI to implement` the function using your comments
- `Review` the generated code by AI. Remove any unecessary lines.
- Write the `time complexity` for the generated solution
- Ask AI for `time complexity`. See if you got it right.
- Now, uncomment tests and you might need to fill unfinished tests. Then verify how long the `Brute force` approach holds.

# Time for optimization when brute force failed
- come up with your own `optimized approach`, communicate the approach with the interviewer. Don't have to make it work.
- (maybe clear chat, for unbiased response) Ask AI to give a list of optimized approaches.
- Choose an approach or ask if about your approach, and weigh the best option and `ask it to implement that`. Communicate to interviewer the approch your decided to go with.
- Re-run tests, fix any issues with code, verify the code manually using console logs / Ask AI to find the isssue in parallel.
